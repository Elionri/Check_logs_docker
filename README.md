# Docker Log Reader

GUI-приложение на Python для просмотра логов Docker-контейнеров в реальном времени
и управления группами контейнеров через `docker compose`.

## Возможности

- **Мультиконтейнерный стриминг** — логи нескольких контейнеров одновременно,
  каждый в своей вкладке.
- **Старт/стоп в один клик** — кнопка `▶`/`■` слева запускает и останавливает
  стрим.
- **Фильтр по уровню** — режим «только CRITICAL/ERROR».
- **Tooltips** — полное имя контейнера при наведении на обрезанное.
- **Тёмная и светлая темы** — переключаются на лету.
- **Docker Compose панель** — запуск команд `docker compose` в нескольких
  директориях с индивидуальными командами и подкомандами.
- **Сохранение задач Compose** между запусками (`~/.config/check_logs/compose.json`).

## Требования

- **Linux** (протестировано на Ubuntu 22.04/24.04; на других дистрибутивах
  должно работать без изменений).
- **Python 3.9+**
- **Docker Engine** с доступным `docker.sock`.
- Пользователь должен быть в группе `docker`:

  ```bash
  sudo usermod -aG docker $USER
  newgrp docker
  ```

- **Tkinter** (нужен для `customtkinter`):

  ```bash
  # Debian / Ubuntu
  sudo apt install python3-tk

  # Fedora
  sudo dnf install python3-tkinter

  # Arch
  sudo pacman -S tk
  ```

## Установка

```bash
git clone https://github.com/<username>/docker-log-reader.git
cd docker-log-reader

python3 -m venv venv
source venv/bin/activate

```

## Использование

### Основное окно

1. Слева — список запущенных Docker-контейнеров.
2. **`▶`** рядом с контейнером — открыть вкладку и запустить стрим логов.
3. **`■`** — остановить стрим и закрыть вкладку.
4. Клик по **имени контейнера** слева — переключиться на уже открытую вкладку.
5. Клик по **вкладке справа** — переключение между логами.
6. **`Старт всех` / `Стоп всех`** — массовое управление.
7. **`Только CRITICAL/ERROR`** — фильтр вывода в реальном времени.
8. **`Очистить всё`** — остановить все стримы и очистить буферы.

> 💡 Инвариант интерфейса: *есть вкладка ⇔ идёт стрим*. Нет «пустых» вкладок,
> нет стримов без вкладки.

### Панель Docker Compose

Кнопка **`🐳 Docker Compose`** в левой панели открывает отдельное окно:

1. Укажите директорию (или выберите через `📁`).
2. Выберите команду (`docker compose` / `docker-compose`).
3. Введите подкоманду (`up -d`, `down`, `restart`, `logs --tail=100` и т. д.).
4. Нажмите **`+ Добавить запись`** — задача появится в списке.
5. Отметьте галочками нужные задачи и нажмите **`▶ Выполнить выбранные`**,
   либо **`▶ Выполнить все`**.
6. Вывод команд стримится в нижнее текстовое поле.

Задачи сохраняются в `~/.config/check_logs/compose.json` и переживают
перезапуск приложения.

## Известные ограничения

- **Только Linux.** Приложение использует `docker.sock` и Linux-пути.
  На macOS/Windows будет работать, но не тестировалось.
- **Не поддерживаются интерактивные TTY-команды** (`docker compose exec`)
  в панели Compose — для этого нужен `pty`, который пока не подключён.
- **`CTkTextbox` не любит миллионы строк.** Если контейнер генерирует очень
  много логов, интерфейс может подтормаживать. Решение: включить фильтр
  или не открывать шумные контейнеры одновременно.
- **Wayland.** На некоторых окружениях `CTkToplevel` с
  `overrideredirect(True)` (используется для tooltips) может отрисовываться
  с задержкой. Запуск через `GDK_BACKEND=x11` решает проблему.

## Разработка

Проект намеренно состоит из двух небольших модулей, чтобы его было легко
дорабатывать.

### Архитектура

- **`Check_logs_new.py`**
  - `ModernLogReader` — главное окно (`ctk.CTk`).
  - `ToolTip` — всплывающие подсказки.
  - Воркеры стриминга — потоки с `container.logs(stream=True, follow=True)`,
    результат передаётся в GUI через `queue.Queue`.
- **`compose_panel.py`**
  - `ComposePanel` — модальное окно (`ctk.CTkToplevel`).
  - Задачи хранятся как список словарей `{dir, cmd, sub, enabled}`.
  - Запуск — `subprocess.Popen(cwd=...)`, вывод — тоже через очередь.

### Принципы

1. **GUI-поток не блокируется.** Все долгие операции — в фоновых потоках,
   обмен через `queue.Queue`, разбор — в `root.after(100, ...)`.
2. **Прерывание стрима** — `stream.close()` из другого потока разбудит
   блокирующий `read()`.
3. **Инвариант вкладок** — состояние стрима и наличие вкладки синхронны.
